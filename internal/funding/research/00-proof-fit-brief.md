## What Proof is

Proof is durable project memory for coding agents. An agent often ends a session and forgets why it chose what it chose; the next session must rebuild the reasoning from code, chat, or issue history. Proof keeps that reasoning beside the code as Markdown under `.flatbread-proof/`, where normal Git diffs and pull requests let people inspect it. An Effort scopes one thread of work. Seven linked record kinds sit under it: Issue, Finding, Decision, Constraint, Risk, Citation, and Blob. Typed relations preserve cause and change: `derives_from` links a claim to upstream evidence or context, `supersedes` replaces an older same-kind record, `invalidates` marks a prior claim wrong, and `cites` points to an external-source Citation. Flatbread validates IDs, kinds, and Effort boundaries. Agents write through typed, journalled mutations and read bounded digests instead of loading the whole graph. The result is portable, human-reviewable memory, not a hosted service or a transcript store.

## Evidence in the repository

- **Eight record directories and 91 dogfood records.** `proofContent()` maps Effort, Issue, Finding, Decision, Constraint, Risk, Citation, and Blob to eight directories (`packages/proof/src/preset.ts:5-76`; `packages/proof/src/ids.ts:14-23`). A direct file count found 91 Markdown records in `.flatbread-proof/`: 5 Efforts, 11 Issues, 32 Findings, 32 Decisions, 7 Constraints, 1 Risk, 2 Citations, and 1 Blob. The repository describes these records as Markdown that people commit, diff, review, and revert (`docs/positioning.md:17-31`).
- **Sixteen typed mutations behind one write command.** The discriminated schema has exactly 16 members, from `CreateEffort` through `Retract` (`packages/proof/src/schemas.ts:23-133`), and a test asserts that count (`packages/proof/src/__tests__/schemas.test.ts:96-101`). The CLI exposes one mutation entry point, `flatbread proof write <json>` (`packages/flatbread/src/cli/proof.ts:425-429`). The reference says each mutation runs in one save-or-undo journal transaction (`packages/proof/skills/proof/reference.md:66-77`).
- **Five bounded reads.** The closed query type contains `getRecord`, `effortRecords`, `relations`, `blockingDecisions`, and `listEfforts` (`packages/proof/src/read.ts:26-51`). Their query-engine implementations are in `packages/flatbread/src/proof/read.ts:493-787`; the CLI names them `get`, `records`, `relations`, `blocking-decisions`, and `list` (`packages/flatbread/src/cli/proof.ts:430-515`).
- **Hard digest bounds.** Production constants cap primary records at 25, displayed edges at 50, and output at 64 KiB (`packages/proof/src/digest.ts:67-69`); the digest header fixes relation expansion at one hop (`packages/proof/src/digest.ts:129-140`). Browse bodies stop at 600 characters or 12 lines (`packages/proof/src/digest.ts:152-161`). Tests cover the 25-record limit and machine-readable cap reason (`packages/proof/src/__tests__/digest.test.ts:179-209`), the byte ceiling (`packages/proof/src/__tests__/digest.test.ts:401-429`), and CLI edge-cap reporting (`packages/flatbread/src/cli/proof.test.ts:443-459`).
- **Journal, recovery, and timing.** Every write runs recovery before planning a new mutation (`packages/proof/src/writer.ts:26-55`). An uncommitted transaction restores before-images; a committed but unpublished transaction reapplies after-images and publishes its generation (`packages/proof/src/journal.ts:86-163`). Recovery runs on a later write or live-server start, not on a read alone (`packages/proof/README.md:196-201`). Recovery tests cover rollback, committed completion, idempotence, and corrupt-intent failure (`packages/proof/src/__tests__/journal-recovery.test.ts:60-137`). The reindex barrier polls every 25 ms and fails after 10 seconds by default (`packages/proof/src/journalBarrier.ts:68-94`).
- **Generation token and strict reads.** A mutation returns a string generation token (`packages/proof/src/types.ts:10-26`; `packages/proof/src/writer.ts:68-72`). A strict read waits until the durable generation reaches that token, polling every 25 ms and timing out after 3000 ms by default (`packages/flatbread/src/proof/read.ts:259-290`). A live-bridge test shows a reader holding a returned token sees the committed mutation (`packages/proof/src/__tests__/live-bridge.test.ts:168-197`).
- **Packaged agent skill and drift checks.** The package ships `skills`, and its scripts provide `skills:sync`, `skills:check`, and `skills:pack-check` (`packages/proof/package.json:6-12,32-35`). The sync script compares canonical and generated trees for missing, changed, and stale files across three managed skills (`packages/proof/scripts/sync-skills.mjs:15-22,49-75,98-110`). Tests check projection sync and read-only drift detection (`packages/proof/src/__tests__/skills.test.ts:11-61`) and reject missing skill files, monorepo-only commands, or release identity drift (`packages/proof/src/__tests__/pack-skills.test.js:28-82`). CI runs both skill checks (`.github/workflows/pipeline.yml:52-56`).
- **CLI surface.** Proof exposes eight commands: `write`, `get`, `blocking-decisions`, `records`, `list`, `bootstrap`, `relations`, and `cache prune` (`packages/flatbread/src/cli/proof.ts:425-520`). The list, records, and relations commands support pages of at most 25; reads support a strict minimum generation and timeout (`packages/flatbread/src/cli/proof.ts:380-389,431-515`).
- **Source and test counts.** A static inventory found 18 production TypeScript modules in `packages/proof/src/`, plus one query-engine bridge in `packages/flatbread/src/proof/` and one CLI adapter: 20 source files for the core Proof read, write, and transport paths. ## Fundable claims

- **Proof has a concrete, inspectable data model, not a concept deck.** It implements 8 record kinds and this repository already uses all 8 across 91 records. Evidence: `packages/proof/src/preset.ts:5-76`; `.flatbread-proof/efforts/eff-effort-graph-memory-and-agent-wedge--szeqvmgqjqnhd002.md:1-9`.
- **The write API is small enough to audit.** One command accepts exactly 16 typed mutations, with schema validation and lifecycle operations rather than free-form file edits. Evidence: `packages/proof/src/schemas.ts:23-133`; `packages/flatbread/src/cli/proof.ts:425-429`; `packages/proof/src/__tests__/schemas.test.ts:96-101`.
- **Recall has enforced context bounds.** Each digest permits at most 25 primary records, 1 relation hop, 50 displayed edges, and 64 KiB. Evidence: `packages/proof/src/digest.ts:67-69,129-140,279-290`; `packages/proof/skills/proof/reference.md:144-162`.
- **The repository contains an initial controlled recall result.** Decision `dec-adopt-a-bounded-status-briefing-fast-path-for-ef--kcw0rw39g3b2ym2h` reports a 12-run experiment and about 52 percent tool-call waste in the unbounded workflow (`.flatbread-proof/decisions/dec-adopt-a-bounded-status-briefing-fast-path-for-ef--kcw0rw39g3b2ym2h.md:2-9,12-31`). Its source Finding states the result exactly: control median 21 tool calls, treatment median 10; ranges did not overlap; Mann-Whitney U=0, two-tailed p ~= 0.0022, Cliff delta=1.0; answer quality was 5/5 in all 12 runs across three model families (`.flatbread-proof/findings/fnd-bounded-status-briefing-protocol-halves-effort-g--ht1jd1hsssf7mv2y.md:9-18`). The Decision remains `proposed`, and the experiment covers one recall question and one graph state.
- **Targeted retrieval can be much smaller than loading cold context.** One dogfood measurement reports 2,225 bytes for a blocking-decision query against 37,101 bytes of cold context, or 94 percent less (`.flatbread-proof/findings/fnd-filtered-retrieval-is-94-percent-smaller--qpvz4vch5hygye20.md:1-11`). It is one representative query, not a general token benchmark.
- **The durability path has explicit failure semantics.** The journal records intent and before-images, uses temporary files and rename, repairs projections, and publishes a generation only after reindex succeeds (`.flatbread-proof/decisions/dec-canonical-forward-edges-and-journaled-save-or-un--sv9x93svkfz4a98r.md:19-30`). Four focused recovery tests cover rollback, completion, repeat recovery, and corrupt input (`packages/proof/src/__tests__/journal-recovery.test.ts:60-137`).
- **The agent instructions ship with the runtime and are checked for drift.** Version `1.1.0` binds the `flatbread` runtime, `@flatbread/proof`, and `v1.1.0` skill source (`packages/proof/skills/proof/release.json:1-6`). The package and CI include sync and packed-payload checks (`packages/proof/package.json:6-12`; `.github/workflows/pipeline.yml:52-56`).
- **The implementation has broad repository test coverage for its size.** Static counting found 204 Proof-related test declarations across 23 files, covering schema, planner, writer, journal, strict reads, CLI integration, live-server composition, and the explorer preset. Evidence: `packages/proof/package.json:6-13`; `packages/proof/src/__tests__/journal-recovery.test.ts:60-137`; `packages/proof/src/__tests__/live-bridge.test.ts:168-204`; `packages/flatbread/src/cli/proof.test.ts:425-459`; `packages/explorer/package.json:6-13`. The suites were counted, not run, in this task.

## Research agenda

The prior evaluation reports tool calls, not provider model calls (`.flatbread-proof/findings/fnd-bounded-status-briefing-protocol-halves-effort-g--ht1jd1hsssf7mv2y.md:9-18`). A tool-using agent may make several model calls per run. Exact call and cash cost is therefore **UNKNOWN** until the harness records provider calls, tokens, model, and price. The budgets below are isolated agent runs, using the repository's three-model, two-condition, two-repetition design as the smallest existing baseline.

1. **Does bounded recall keep its quality on harder questions?** The current Decision says to revisit if quality falls on richer recall tasks or if needed body detail is missed (`.flatbread-proof/decisions/dec-adopt-a-bounded-status-briefing-fast-path-for-ef--kcw0rw39g3b2ym2h.md:29-31`). Test four tasks: status, rationale, supersession history, and risk/constraint synthesis. Compare the current bounded workflow with unconstrained exploration across three model families and two repetitions. Budget: 48 agent runs; provider model calls UNKNOWN until instrumented.
2. **Where do the read caps fail as a graph grows?** The current path fixes 25 records, one hop, 50 edges, and 64 KiB (`packages/proof/src/digest.ts:67-69,129-140`), while full-body `get` can fail closed at the byte cap (`.flatbread-proof/decisions/dec-effort-get-digests-always-include-the-full-recor--xs7rnbha3zx8qdj9.md:17-37`). Build small, medium, and cap-crossing graphs from the same facts; ask the same recall question with and without paging. A 3 sizes × 2 workflows × 3 models × 2 repetitions design costs 36 agent runs; provider model calls UNKNOWN until instrumented.
3. **Do typed edges change a later agent's decisions, or only make lookup neat?** Proof makes `derives_from`, `supersedes`, `invalidates`, and `cites` causal structure (`packages/proof/README.md:39-44`). Give agents matched repositories with the same prose, once with valid relations and once with relation fields removed. Measure whether they recover the current Decision, reject invalidated evidence, and cite the right source. A 2 graph forms × 3 models × 2 repetitions design costs 12 agent runs; provider model calls UNKNOWN until instrumented.
4. **Does bounded retrieval reduce tokens as well as round trips?** One measurement found 2,225 bytes versus 37,101 bytes (`.flatbread-proof/findings/fnd-filtered-retrieval-is-94-percent-smaller--qpvz4vch5hygye20.md:1-11`), but the 12-run recall study says estimated bytes were roughly flat and self-reported (`.flatbread-proof/findings/fnd-bounded-status-briefing-protocol-halves-effort-g--ht1jd1hsssf7mv2y.md:14-18`). Repeat the two workflows with provider-side input, output, cache, latency, and cost logs. The existing 3 × 2 × 2 design costs 12 agent runs; provider calls become a measured result, not an estimate.
5. **Does the 4/4 write gate improve future memory?** The skill admits records only for future need, durable effect, causal value, and unique signal (`packages/proof/skills/proof/SKILL.md:54-85`), and release 1.1.0 includes four manual eval cases (`CHANGELOG.md:19-22`). Run those four cases with and without the gate, then give a later agent the resulting graph and score recall, noise, and wrong causal links. A 4 cases × 2 gate conditions × 3 models × 2 repetitions design costs 48 writer runs plus 48 later-reader runs; provider model calls UNKNOWN until instrumented.

## Anti-claims

- **Not a hosted memory service, CMS, authoring UI, or task tracker.** Those framings conflict with the package and glossary (`packages/proof/README.md:18-20`; `packages/proof/skills/proof/glossary.md:3-10`). Programs that require a hosted SaaS product or paid cloud tier are a poor fit unless the scope changes.
- **Not a general database or GraphQL platform.** Transactions, detailed access control, and many concurrent writers are outside Flatbread's scope (`docs/positioning.md:45-50`). Database infrastructure grants should only be used when their scope clearly includes file-backed developer tools.
- **Not semantic search or a vector-memory system.** The product is a typed relational graph with closed, bounded reads. The lead-use-case Decision says the release did not add semantic search or a hosted CMS (`.flatbread-proof/decisions/dec-lead-flatbread-1-0-with-effort-graph-agent-memor--nhxsqm8sd43s2avx.md:11-21`).
- **Not a transcript archive.** Proof keeps a small set of durable reasons, while routine progress belongs in a pull request or issue (`packages/proof/README.md:18-20,156-161`). Full transcripts also carry prompt-overflow and secret-leak risk (`.flatbread-proof/risks/rsk-full-transcripts-can-overflow-prompts-and-leak-s--3p7ybk07jqe5w593.md:1-11`).
- **Not proven at broad research scale.** The strongest recall result covers one question, one graph state, 12 runs, and self-reported counts (`.flatbread-proof/findings/fnd-bounded-status-briefing-protocol-halves-effort-g--ht1jd1hsssf7mv2y.md:9-18`). Do not pitch it as a settled benchmark or claim that it improves answer quality.
- **Not proven to be a company, US or EU entity, non-profit, or academic project.** The repository does not settle those gates. Screen out entity-, country-, charity-, and university-only programs until Tony Ketcham supplies the missing facts.
- **Not a mature multi-maintainer foundation project on repository evidence.** The tree names one package author but gives no formal governance or contributor count (`package.json:49-54`). Do not claim broad governance, institutional backing, or a large contributor base.
- **Not a claim that all 91 dogfood records are current product truth.** Records retain superseded and proposed history. Current code, current docs, lifecycle state, and relation heads must decide what is live (`packages/proof/skills/proof/glossary.md:33-38,68-78`).
